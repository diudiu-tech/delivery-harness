# Delivery Harness v2 API

2026-09-30。与[产品 PRD](../prd/delivery-harness-product-prd.md)和[实施映射](../implementation/delivery-harness-prd-implementation.md)配套。服务默认 `http://127.0.0.1:8080`，工作台 `/workbench/`。JSON 字段以本文件和实际 Controller 为准，v1 仅供 demo 兼容。

## 身份与通用约定

pilot 的每个 `/api/**` 请求都需要 `Authorization: Bearer <token>`。角色、租户、城市和站点仅从服务器配置解析；请求体的身份字段无效。demo 无令牌使用 `demo-agent`，配置第二个身份才能完成独立核验/发布。未知令牌在 demo 中同样返回 401。

v2 使用两种明确响应：案件、执行和支付为扁平对象；政策、知识、配置、数据集/运行/结果为 `{id,tenantId,kind,version,createdAt,updatedAt,data}` 版本记录。集合为 `{items,next_cursor}`，案件为 `{items,cursor}`，部分审计接口返回数组。工作台统一展开版本记录。更新时间是 ISO-8601；金额是十进制定值及 CNY；未测量字段可能被 JSON 配置省略，应按 unknown 处理。

错误对象 `{code,message}`；401 身份不明、403 动作不许可、404 不存在或范围不可见、409 版本/幂等/政策/状态冲突、422 明显个人信息或语义校验不通过、429 队列或租户配额、502 上游格式不符、503 源不可用、504 超时。并发写携带 `expected_version`；执行和人工例外使用 `expected_case_version`。收到 409 后重新读取当前证据和版本，不自动重试审批。在线执行返回 202；失败结果通过 execution 查询。

角色按动作授权，`ADMIN` 不自动具有所有业务角色。scope 的 `*` 表示该维度全部范围；城市和站点两个维度同时满足。

| 角色 | 主要动作 |
| --- | --- |
| AGENT / OPERATOR | 建案、补证、分析、取消；OPERATOR 可导出 |
| REVIEWER / SUPERVISOR | 核验材料、领取、审批/退回/转派；高风险和例外需要 SUPERVISOR |
| POLICY_EDITOR / POLICY_PUBLISHER | 起草/校验；独立发布政策、知识 |
| QUALITY / ADMIN | 配置、数据集、评测、发布及反馈生命周期 |
| AUDITOR | 范围内审计/导出/资金查单、保留锁 |
| FUNDS | 独立、受控的支付提交/查单；不授予材料或审批写权限 |
| PAYMENT_CALLBACK | 签名渠道事件；仍需租户和案件范围匹配 |

## 案件、证据和人工流程

| 方法与路径（均在 `/api/v2` 下） | 请求要点 / 响应 |
| --- | --- |
| GET `/session` | mode、可信 principal、Adapter 状态 |
| POST `/cases` | `order_id,complaint_type`；可选 `source_ticket_id,title`；投诉 OVERTIME/DAMAGED/WRONG_ORDER/MISSING_ITEM |
| GET `/cases?limit=20&cursor=...` | 1–100，数据库先过滤 scope，再按风险、到期和创建顺序分页 |
| GET `/cases/{id}` | 当前决定、快照、材料、review、操作历史；普通视图隐藏姓名/地址/附件正文/模型原文 |
| POST `/cases/{id}/evidence` | `description,source,file_hash,size_bytes,mime_type,content_base64`；可选 damage_level=FULL/PARTIAL |
| POST `/materials/{id}/review` | `action=VERIFY/REJECT,reason,expected_version`；上传人不能自核验；仅冻结校验过的正文可VERIFY |
| GET `/materials/{id}/content` | 需要案件权限，附件限 MIME、大小和内容签名；外部 URL 元数据不构成已核验事实 |
| GET `/evidence/{id}` | 按关联案件范围读取冻结快照 |
| GET `/reviews` | 当前 scope 的待办 |
| POST `/reviews/{id}/claim` | `expected_version`；并发只能一人领取 |
| POST `/reviews/{id}/actions` | `expected_version,action,reason,decision_id,decision_version,evidence_snapshot_id`；REASSIGN 另传 target_user_id |
| POST `/cases/{id}/exceptions` | `expected_case_version,evidence_snapshot_id,amount,method,reason,authorization_basis`；新增例外决定，需要另一主管批准 |
| POST `/cases/{id}/close` | `expected_version,reason`，可选 existing-system `external_receipt`；审批与支付状态独立 |
| GET `/cases/{id}/export` | 脱敏、范围受控结构化 JSON；写导出审计；模型草稿不能冒充核验话术 |

Inline 正文最大 1 MB，登记元数据最大 10 MB，允许 PNG/JPEG/PDF/text；SHA-256 必须与实际字节匹配。补证或材料审核会生成新的证据引用并使旧审批失效。资金 PENDING/SUBMITTED/UNKNOWN/SUCCEEDED 期间禁止重写证据、决定和审批；先按台账处理支付结果。

## 执行

```bash
curl --fail-with-body -X POST http://127.0.0.1:8080/api/v2/executions \
  -H 'Content-Type: application/json' -H 'Idempotency-Key: ticket-001-comp-v1' \
  -d '{"case_id":"<case-id>","scenario":"compensation_suggestion","runtime_config_id":"runtime-default-v1","expected_case_version":1}'
```

scenario 为 `abnormal_order_analysis` 或 `compensation_suggestion`；DAMAGED 可传 damage_level，但 `damage_evidence_verified` 不接受客户端授权。冻结核验状态仅来自同一事务的材料版本。相同身份/操作/幂等键和相同正文返回同任务；不同正文 409。建议保存 24 小时以上，记录不会静默淘汰。GET `/executions/{id}`、GET `/executions?limit=20&cursor=...`、POST `/executions/{id}/cancel`、GET `/executions/queue-status` 提供轮询、取消和队列状态。

终态 SUCCESS/DEGRADED/FAILED/TIMED_OUT/CANCELLED。模型、ETA、历史运力等可选依赖缺失显示 DEGRADED；订单源/审计等必需依赖失败留下同一 execution 的失败原因和已完成步骤。未知金额不是 0。决定状态 DETERMINED/INSUFFICIENT_EVIDENCE/OUT_OF_SCOPE/POLICY_CONFLICT，客服核验说明来自服务端确定性模板，模型原文保持草稿。

## 政策、知识和真实配置

| 资源 | 接口与关键约束 |
| --- | --- |
| 政策 | GET/POST `/policies/versions`、GET `/{id}`、POST `/{id}/validate,publish,withdraw`。发布/撤回需 expected_version；发布人独立于作者；范围和生效日期可配置 |
| 知识 | POST `/knowledge/versions/preview`；GET/POST `/knowledge/versions`、GET `/{id}`；POST `/{id}/review,publish,withdraw` 携带 expected_version、reason |
| 检索 | POST `/knowledge/search`：query,top_k,city_code,station_id,as_of 可选；规则 ID 精确命中、中文关键词/同义词；结果 score 是相关性而非可信概率 |
| 引用 | GET `/knowledge/citations/{id}`；引用 ID `policyVersion:ruleId` 或 `knowledgeVersion:chunkOffset`，按版本与范围验证 |
| 配置 | GET/POST `/runtime-configs`、GET `/{id}`；POST `/{id}/probe`、POST `/{id}/publish`：expected_version,eval_run_id |
| 灰度路由 | GET/POST `/runtime-routes`；场景与 scope 选择 primary/fallback 发布配置；primary_config_id,fallback_config_id,rollout_percent(0–100),city_codes,station_ids；稳定案件散列分配候选；仅未传runtime_config_id时使用路由，决定保存真正命中的配置 |

知识预览保留切片与风险诊断；含可识别手机号、邮箱、身份证或明确姓名/地址标签的版本不能发布，先脱敏后建立新版本。运行 Prompt 与冻结内容在模型绑定前同样检查。这些规则检查不代表全面自然语言个人信息识别。

配置创建必须带 `model,prompt,policy_version`；可选 knowledge_versions、deterministic_only、temperature(0–2)、max_tokens(1–8192)、timeout_seconds(1–120)、max_retries(0–2)、pricing（version,currency=CNY/USD,input_per_million,output_per_million）。仅支持管理员配置的 `endpoint_ref=configured-default`，不能通过 API 注入任意 URL。完整 prompt/规则/知识/hash 被冻结；新修改创建新 ID。上线需要确切同配置通过标注门禁，且发布者不能是作者。撤回政策/资料阻断新运行；历史运行按保存快照重放。

政策 request.rules 是 RuleInfo 数组：ruleId,ruleName,ruleType,enabled,priority,currency,conditions,actions,content；超时明确按完整分钟 FLOOR 取整并保留原始秒，公式 FIXED/PERCENT_CAPPED/DAMAGE_LEVEL/MANUAL 带精确币种/封顶和材料条件。发布前冲突、异常类型、金额和数值边界被校验，coverage_gaps 列出未覆盖分钟区间；有缺口时该区间仍为 OUT_OF_SCOPE；没有缺件规则不自动变成拒赔。以 GET 默认 demo 政策中的完整规则作为结构参考。

## 可复现评测与反馈

GET/POST `/eval/datasets`、GET `/eval/datasets/{id}` 创建只追加数据集。split 为 SYNTHETIC_SMOKE/BOUNDARY_REGRESSION/REAL_LABELLED/FROZEN_BLIND；samples 每条含 sample_id、scenario、input、evidence_order 或创建时从只读源冻结、expected_output、expected_rule_ids。赔付门禁至少需要明确的 amount/currency/decision_status；未标注报告 NOT_MEASURED，不能发布。数据集 hash、防盲测内容泄漏、版本 scope 由服务器校验。

POST `/eval/runs`：dataset_version,runtime_config_id；GET列表/单项、GET `/{id}/results`、POST `/{id}/cancel,replay,retry`；GET `/{id}/compare/{candidateId}`。独立线程池执行、保存进度 completed/total、真实请求 prompt/config hash、git_sha、evidence hash、规则 precision/recall/exact-match、分维度 scores。金额差 0.01 也失败；关键证据错误不能靠其他平均分掩盖。replay 使用已保存执行输出重新评分；要重新调用模型，创建新 run，历史结果不覆盖。重启中断的评测标明 FAILED/恢复原因，通过冻结新 run 恢复。

GET/POST `/feedback`；POST `/feedback/{id}/status`：expected_version,status,reason，可选 issue_ref/eval_run_id。创建绑定 case_id、decision_id、decision_version、category 和 correction 对象：reason_code,field_path,original_value,suggested_value,evidence_refs。原值必须对应不可变决定；核验者不能是提交人。生命周期 PENDING_VERIFICATION→CONFIRMED→LINKED_FIX→REGRESSION_VERIFIED；也可独立拒绝进入REJECTED终态。最后阶段需通过包含该反馈source_feedback_id及原证据快照的有效评测。

## 运营、留存与支付扩展

GET `/metrics` 提供 SUCCESS/DEGRADED/失败分别统计及原始耗时 p50/p95/p99；提供方未回传 token/无价格时费用 unknown。GET `/audit-events?limit=20&cursor=<ISO-time>` 是 scope 内审计；业务写与审计原子提交。

POST `/cases/{id}/retention-hold`：locked,reason；修改已有锁需 expected_version。POST `/retention/plans`：case_id,reason；GET `/retention/plans/{id}`；POST `/{id}/approve`：expected_version,graph_hash,reason。默认只生成 dry-run，执行需 HARNESS_RETENTION_ENABLED=true 且独立 ADMIN。未结案、保留期内、保留锁、资金引用或评测仍引用的案件拒绝删除；图变化也拒绝。审批删除案内材料/快照/决定/执行/审核/反馈/幂等数据并保留无正文的审计与回执，全部一个事务。评测/资金引用的退役必须经单独数据迁移审核，不能自动级联删除。

资金接口默认关闭：POST `/compensations` 需要 FUNDS、稳定 compensation_id、case_id、decision_id、decision_version。GET `/{id}`；POST `/{id}/reconcile` 查单；POST `/{id}/callback` 需要 PAYMENT_CALLBACK 和签名。审批不触发支付。渠道提供 fresh eligibility（最多 180 秒）、原子版本约束、金额和币种复核、幂等和查单；累计和未决占用超额度拦截。PENDING outbox 恢复可提交；SUBMITTED/UNKNOWN 只查单。旧台账回调不能覆盖当前案件资金状态。

签名 canonical payload 递归排序 map keys、保持数组顺序，并对数字stripTrailingZeros后按Jackson BigDecimal编码（20可能表示2E+1），再做 SHA-256；跨语言渠道建议amount使用固定两位十进制字符串以消除数值编码歧义。待签文本为 `tenant_id + "\n" + timestamp + "\n" + event_id + "\n" + compensation_id + "\n" + payload_sha256`，HMAC-SHA256 十六进制。头部 X-Event-Id/X-Callback-Timestamp/X-Callback-Signature，时间窗口 ±300秒。payload amount,currency,status,external_id；同事件幂等，冲突终态需要人工对账。详见[运行手册](../operations/pilot-runbook.md)的真实源与支付契约。
